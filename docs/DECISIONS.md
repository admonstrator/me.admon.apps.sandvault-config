# Decisions

Numbered decisions, one table per phase. Briefs and reports are measured against these rows.

## Phase 0 · Direction (2026-10-09)

| No. | Question | Decision |
|---|---|---|
| D1 | User interface | Native macOS app (SwiftUI, MenuBarExtra + window) plus the `svctl` CLI |
| D2 | Technology | Swift only, no Rust. Core modules as a SwiftPM package (testable on Linux), app as an Xcode project generated by XcodeGen (`App/project.yml`; `.xcodeproj` is not committed) |
| D3 | Relation to `sv` | Complement: `sv` / `sv-clone` keep installing the sandbox and starting sessions; we read, control and extend |
| D4 | How rules take effect | Managed block between markers at the end of `/var/sandvault/sandbox-sandvault-$USER.sb`, validated with `sandbox-exec -f <candidate> /usr/bin/true` before it is written; drift after `sv --rebuild` is detected and can be re-applied |
| D5 | Language | UI, CLI and messages in English; README with a German section; code, comments, commits in English |
| D6 | Network | Connection monitor + per-user pf firewall + proxy/DNS with prompts + optional TLS inspection; no Network Extension |
| D7 | Control | Rule editor + learn mode, "hardened" preset with panic switch and integrity check, granting commands |
| D8 | Workflow | Repository hand-off to an agent, way back and repo status, processes and sessions, config migration |
| D9 | Root privileges | Root-owned helper at `/Library/PrivilegedHelperTools/me.admon.apps.sandvault-config.helper`, allowed by `/etc/sudoers.d/60-sandvault-config-$USER` (the way `sv` does it); installed once with an admin password; accepts typed JSON only, never SBPL or pf text |
| D10 | Proxy technology | SwiftNIO + swift-nio-ssl + swift-certificates (run on Linux, testable here) |
| D11 | Minimum version | macOS 26 (raised from 14 on 2026-10-10), Swift 6 language mode |
| D12 | Later | Secret scan, audit log, Network Extension, localization, signing/notarization, license file |

## Phase 1 · Results that became rules (2026-10-09)

| No. | Question | Decision |
|---|---|---|
| D19 | Helper sudoers rule | Argument-exact: the rule lists every unattended call (`PrivilegedHelper.unattendedArguments`, e.g. `<helper> pf-apply --json`), never the bare helper path. Otherwise any host process could run `sudo -n <helper> install --source <own binary>` and get root. `install`, `uninstall`, `restore` are unreachable through `sudo -n` |
| D20 | Panic | `panic` latches in the root state: `pf-apply` stays `blocked` until a call with `--release-panic` (CLI/app `apply`), so netd's port refresh cannot silently undo it |
| D21 | One owner per Mac | The pf anchor belongs to one host user; a second user is refused with a clear message |
| D22 | netd and asks | netd raises asks only while a client subscribes to `.asks`; otherwise `askFallback` applies immediately |
| D23 | Upstream DNS | First `nameserver` of `/etc/resolv.conf` (overridable with `--upstream-dns`); split DNS over VPN is not followed yet |

## Phase 2 · Results that became rules (2026-10-09)

| No. | Question | Decision |
|---|---|---|
| D29 | Git on sandbox clones | Only as the sandbox user under sv's profile (`SandboxedCommand.git`); output parsed as untrusted text. The host runs git only in the host repository (`fetch sandvault --no-tags --no-recurse-submodules` with `GitSafe`) |

## Device feedback (2026-10-09)

| No. | Question | Decision |
|---|---|---|
| D33 | Seeing host names without blocking | New firewall mode `watch`: 80/443/53 go through netd as in `proxyOnly`, everything else passes as in `open`; netd refuses only what a `deny` rule names. Most lookups go through mDNSResponder, so host names come from SNI and `Host`, not from DNS |
| D34 | ICMP | pf cannot match ICMP to a user and `ping` is setuid root: it is shown (process list, real user), not filtered. Only an exec rule stops it |
| D35 | App for end users | Simple window by default (Overview, Activity, Repos & Hand-off, Settings) with four protection levels applied without a rule preview; expert mode shows every page |
| D36 | Managing the sandbox | One sandbox per macOS user, as sv defines it. The app creates, rebuilds and deletes it only through `sv build`, `sv --rebuild build` and `sv uninstall` in a terminal window, where sv asks for the password; it never edits accounts itself. A rebuild from the app is followed by `svctl rules apply` (D31 still refuses `--rebuild` as a session option) |

## Phase 4 · Connection requests with details (2026-10-10)

| No. | Question | Decision |
|---|---|---|
| D37 | Other ports in Ask | In proxy-only mode pf hands every TCP port other than 53, 80 and 443 to netd's transparent TCP listener (`ProxyPorts.transparentTCP`, `NetworkPolicy.routeAllTCP`, default on); netd finds the original destination as for TLS without SNI and decides with rules and asks. `DomainRule.port` limits a rule to one port; `AskScope.hostAndPort` saves such a rule. UDP other than DNS stays refused |
| D38 | Who collects the details | netd, before it publishes the ask, within `AskDetailSettings.budgetSeconds` (1.5 s); each lookup can be turned off in Settings and whatever is late is left out. The app only displays `AskRequest.details` |
| D39 | Lookups and privacy | Name (DNS answers through netd, SNI, Host), port list, program signature and history stay on the Mac. Reverse DNS asks the upstream DNS server. Network owner and country: an offline table (iptoasn.com, downloaded on request to `AppPaths.networkDatabase`) or RDAP online, which reveals the address to the registry |
| D40 | Assessment | Points per signal, each with a sentence and the detail it belongs to; below 3 normal, 3 to 5 unusual, 6 and more suspicious. Countries count only when the user marked them (empty by default) and never on their own |
| D41 | Panel | One row at the bottom: a menu for how long the answer counts (just once or a rule for the offered scopes), then Deny and Allow of equal size. Details as tiles, red for signals against; with the safer default a suspicious request makes Deny the default button |

## Phase 5 · Recording web traffic, files and programs (2026-10-10)

| No. | Question | Decision |
|---|---|---|
| D42 | Seeing web traffic | Activity gets a Web traffic view: one row per `HTTPSummary` with program, method, address, status, sizes and duration, and the request and response headers on click (sensitive headers redacted as before). An HTTPS connection without inspection shows its name, size and duration only, marked as encrypted. `WebRecordingSettings.requests` (default on) |
| D43 | Bodies | Off by default (`WebRecordingSettings.contents`). netd keeps up to `maxContentBytes` (1 MB) per body in `AppPaths.httpContentDir`, one file per `StoredContent.id`, deletes them after `retentionDays` (7) and serves them over `ControlRequest.content`. Bodies are stored as sent; only headers are redacted |
| D44 | Recording files and programs | Opt-in (`ActivityRecordingSettings.enabled`). The app starts `sudo -n svctl-helper activity-record --json`; the helper runs macOS's `eslogger` (exec, open, close, create, write, rename, unlink), keeps only processes of the sandbox user and prints `ActivityStreamLine`s. It records while the app runs. macOS requires Full Disk Access for the responsible app; without it the helper reports `needsFullDiskAccess`. The new argv needs a helper reinstall (sudoers rule) |
| D45 | Storing activity | The app filters before it stores: without `openAndClose` it keeps exec, create, write, rename, delete and closes that changed a file, plus one open per file and minute; `hideSystemFiles` drops reads of system locations. JSON Lines in `AppPaths.activityLog`, older than `retentionDays` (7) removed. The view summarises per program (read, changed, created, deleted, started) and lists every event under Everything; sensitive places (SSH, keychains, other homes, browser profiles) are marked |
| D46 | Learn mode for everyone | Each suggestion is one sentence in plain words ("claude wanted to create and change files in ~/Documents/Notes"), with at most two allow choices (this file or this folder, read only or read and write) and Keep Blocked. The raw log line stays under Details. Known system services get names; unknown ones stay technical |

## Docker Sandboxes as a second target (2026-10-15)

| No. | Question | Decision |
|---|---|---|
| D47 | Linux VMs next to sv | Docker Sandboxes (`sbx`) become an optional hand-off target, only when `sbx` is installed (`/opt/homebrew/bin` or `/usr/local/bin`). The app drives it through the `sbx` command line only: `sbx run --name sv-<repo> --clone <agent> <folder> [-- <task>]` in the terminal, `sbx ls --json`, `sbx stop`, `sbx rm --force`, and `git fetch sandbox-<name>` in the host folder for the way back. sbx takes local folders only, so a URL is cloned into `HandoffSettings.cloneDirectory` (default `~/git`) by `git clone` in the same terminal line, with the user's own git login. No briefing, no uncommitted changes, no deploy keys and no sv options for this target; pi and muse have no sbx template. pf, the helper, the sandbox profile and netd do not see these VMs; sbx's own network policy applies. The Sandbox page warns when `ssh.agentForwardingEnabled` is on |

## Android emulator in the sandbox (2026-10-15)

| No. | Question | Decision |
|---|---|---|
| D48 | Android SDK for the sandbox | sv's profile denies reads under the host home, so the host SDK (`ANDROID_HOME`, `ANDROID_SDK_ROOT`, `~/Library/Android/sdk`, Homebrew's command-line tools) is cloned with `clonefileat` into `$SHARED_WORKSPACE/android/sdk`: same APFS volume, no extra space, host-owned and read-only for the sandbox; the host never runs anything from that copy. "Update" clones again and swaps the directory. Devices live in `$SHARED_WORKSPACE/android/avd` (sandbox-writable); a host device comes over as `config.ini` only, with SDK paths rewritten, host-home paths and the SD card dropped, so user data and snapshots stay on the host. A managed `android` block in `$SHARED_WORKSPACE/user/.zshenv` sets `ANDROID_HOME`, `ANDROID_SDK_ROOT`, `ANDROID_AVD_HOME` and `PATH`. sv sessions run over SSH without a window server, so the emulator runs with `-no-window`; the check runs `emulator -version`, `-list-avds`, `-accel-check` and `adb version` as the sandbox user inside the profile |

## Chrome in the sandbox (2026-10-15)

| No. | Question | Decision |
|---|---|---|
| D49 | Chrome inside the sandbox and the inspection CA | Chrome on macOS ignores `SSL_CERT_FILE` and takes trust from the keychain of the user it runs as. A trust setting in the sandbox user's login keychain needs an interactive confirmation that user cannot give, and admin-domain trust would make every browser on the Mac trust the inspection CA, so neither is used. `CAPublisher` writes `_sandvault-config/sandvault-chrome` (0755) instead, exported as `SANDVAULT_CHROME` while inspection is on: it starts Chrome (or `SANDVAULT_CHROME_BINARY`) with `--ignore-certificate-errors-spki-list=<base64 SHA-256 of the CA's SubjectPublicKeyInfo>`, its own `--user-data-dir` (default `~/.cache/sandvault-chrome`, required for that flag), `--proxy-server` from `HTTPS_PROXY`, and passes all arguments on, so Playwright and Puppeteer can use it as `executablePath`. netd always sends the CA after the leaf, so the key is in every chain. Chrome stays the browser of choice: Firefox has dropped CDP and only takes CAs through an app-wide policy file, Safari and WebKit read the same keychain |

## Live web traffic (2026-10-15)

| No. | Question | Decision |
|---|---|---|
| D50 | Requests of open connections | A tunnel (CONNECT or transparent TLS, inspected or not) publishes a snapshot of its unfinished record when it is established and after each request summary: `ControlEvent.update` on the new topic `ControlTopic.live`; `ControlRequest.openConnections` returns the latest snapshot of every open tunnel. The finished `.connection` with the same id replaces the snapshot; the log and `svctl netlog` still get finished records only. The app subscribes to `.live` separately and tolerates a netd that refuses it. Full snapshots rather than deltas, so a client that connects late is complete after one event; the 200 summaries per record bound their size |

## Process details (2026-10-15)

| No. | Question | Decision |
|---|---|---|
| D51 | What one process did | Put together, not recorded anew: `ProcessTracer` (SandvaultObserve) indexes the stored `FileActivityEvent`s, netd's `ConnectionRecord`s and pending `AskRequest`s (both carry the pid netd found with lsof) and the latest `ps` snapshot. A process is a pid plus its start time (`TracedProcess.id` `<pid>@<ms>`), because pids are reused: the helper now also keeps eslogger's `original_ppid` (else `ppid`), `start_time`, `signing_id` and a signature from `is_platform_binary`, `codesigning_flags` and `team_id`, plus `cwd` on exec, as optional fields of `FileActivityEvent`; a running process from `ps` matches a recorded one with the same pid when the starts differ by at most 2 s. A connection or older event without a start goes to the process with its pid that started last before it. The parent is the process with the parent pid that started last before the child; loops end the chain. `ProcessReference` (pid and a moment it existed) names a process across windows and the command line. The app (`ProcessDetailModel`, `ProcessDetail`) groups alike events per process (requests by method, host and path; files by action and folder as in D45; starts by program), marks sensitive places as D45 does plus launch agents and daemons and starting `/usr/bin/security`, and opens one window per process (`ProcessDetailView`, `WindowGroup` for `ProcessReference`). `svctl activity process <pid> [--at] [--no-children] [--json]` prints the same trace ungrouped. eslogger field names are taken from Apple's documentation, not from a capture; every new field is optional and a field of the wrong type is dropped, never the event |
